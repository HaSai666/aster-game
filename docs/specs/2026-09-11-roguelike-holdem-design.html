霓虹地下牌局

德州的下注与诈唬，加上保密的肉鸽构筑。朋友同桌竞争，每个阶段都有重新争胜的机会。

1–5 名真人 · 固定 5 人桌 · Bot 补位 · 25 手 · 目标 30–45 分钟

局域网浏览器游戏，房主电脑运行服务。玩法、交互、视听和联机方向已逐节确认；本文为待最终审阅的设计文档，不代表游戏已经实现。

01 / 方案与产品边界

已选择 · 成长与经营兼顾

短阶段成长赛

5 阶段 × 5 手。开局及前四阶段结束时三选一，共获得 5 个能力。

每阶段每个座位当一次庄，成长频繁。25 手的真实耗时需试玩验证。

备选 · 更重筹码经营

长阶段经营赛

3 阶段 × 10 手。开局及阶段间选能力，共获得 3 个能力。

跨手决策更充分，但成长间隔长，肉鸽体验出现得较慢。

备选 · 更快形成构筑

快速构筑赛

5 阶段 × 3 手，能力选择节奏与短阶段方案一致。

总手数少，但单阶段庄位不均，排名更受发牌运气影响。

目标体验：玩家既读底牌与下注，也根据公开动作推测对方构筑；能力明显改变策略，标准德州牌型与下注骨架保持稳定。

首版包含
局域网开房、电脑和手机浏览器、Bot 补位、完整积分赛、隐藏能力、断线回桌、霓虹视听反馈。
首版边界
不包含公网匹配、异地一键联机、账号与长期成长、商店、能力升级、观战席、房主迁移或中断存档恢复。局内筹码与积分仅服务比赛。
当前项目
仓库目前只有 README 和初始提交，没有需要兼容的现有游戏实现。

02 / 一场比赛如何进行

房主启动服务 → 浏览器入座 → Bot 补足 5 人 → 开局三选一
    ↓
阶段开始：每人 1,000 筹码，补发记录归零
    ↓
连续 5 手德州：庄位逐手顺移，输光者下一手补筹码
    ↓
按调整后筹码排名 → 发放阶段积分
    ├─ 第 1–4 阶段：同时三选一 → 下一阶段
    └─ 第 5 阶段：累计积分 → 最终排名
项目规则
座位与庄位固定 5 个座位，开局随机确定庄位，之后每手顺移一位。开赛后固定席位，不开放新玩家中途替换 Bot；原玩家可重连。
基础德州标准 52 张牌、无大小王；每人两张底牌，共五张公共牌，七选五比较标准牌型，花色不分大小。采用无限注德州，包含最小加注、短码全押与边池规则。
盲注与筹码每阶段初始 1,000，小盲／大盲 10／20，整场固定，无前注。筹码采用整数单位。具体数值是首轮试玩基准。
补筹码只给手牌结算后余额为 0 的座位补发；下一手开始前补至 1,000，累计记录本阶段补发额。余额大于 0 不补发。阶段最后一手后直接结算，不做无意义补发。
阶段成绩排名筹码 = 剩余筹码 − 本阶段累计补发额，允许负数。补发既不改变已结束的底池，也不清除输牌代价。
积分第一至第五得 5／3／2／1／0 分。筹码成绩并列，平分所占名次积分；内部保留精确值，不用显示舍入值判断胜负。
阶段重置筹码统一恢复 1,000，补发记录清零。已获得能力和总积分保留；能力的阶段次数及阶段资源按定义重置。
最终排名五阶段总积分降序，总分相同共享名次，不额外加赛。Bot 参与同一计分与排名。

补发示例：输光 1,000，补发 1,000 后结束时剩 1,400，排名筹码为 400。拿补发筹码继续玩仍需承担此前损失。

并列示例：两人并列第二，各得 (3 + 2) ÷ 2 = 2.5 分；三人并列第三，各得 (2 + 1 + 0) ÷ 3 = 1 分。

平分底池时，无法均分的整数余筹按庄位左侧起的座位顺序分给对应获胜者。无人跟注时不强制亮牌；进入摊牌时公开仍参与争夺底池者的底牌，已弃牌者保持保密。

阶段末为抢名次而冒险全押属于本设计接受的策略。试玩重点检查其是否压倒其他打法。30–45 分钟是目标，20 秒逐次行动仍可能让部分牌局超过目标时长。

03 / 保密构筑与能力边界

  • 每次独立提供 3 个不同能力，排除自己已有能力；不同玩家可拥有相同能力。首版没有稀有度、刷新、升级或背包替换。
  • 开局选一次，前四阶段结束后各选一次，最终携带 5 个能力。能力应独立可用，组合后拓展打法。
  • 主动能力仅在本人下注行动前发动，每次行动最多一个；之后仍须下注或弃牌，使用能力不重置计时。全押后自动发牌期间不提供能力窗口。
  • 能力列表、触发条件、剩余次数及积攒资源只对本人显示。必要动作进入公开记录，私密结果仅发送给本人。
  • 换牌从当前剩余牌堆取牌，旧牌移入本手弃置区，不再抽回；查看不会取走或改动牌。首版能力不直接生成筹码。
能力示例效果与时机公开信息
换手每阶段一次；翻牌后，在自己的合法行动窗口选择一张底牌随机换掉。“某玩家换了 1 张底牌”。新旧牌及能力名称保密。
忍耐每主动弃牌两次获得一次换牌机会，最多存一次，阶段结束清空。机会沿用换手的发动时机；储存已满时暂停积攒，消耗后重新从零积攒。超时自动弃牌不计入。正常弃牌记录；真正换牌时显示通用换牌记录，来源保密。
侦察每阶段一次，在自己的合法行动窗口选择一名仍在本手的对手，随机查看其一张当前底牌。该信息是查看时的快照，不随对方后续换牌更新。“某玩家侦察了某玩家”，具体牌仅本人可见。

这些是已认可的强度示例，不是完整能力库。五次均提供三个未拥有选项，能力库至少需要 7 个不同能力；只有上述 3 个示例不足以实现完整构筑流程。完整目录属于后续内容设计工作，须逐项定义时机、资源、公开范围、组合与 Bot 用法。

为避免选择信息泄漏，其他玩家只看到是否选完，不能看到候选项。通用公开动作可能帮助对手推测流派，这是预期博弈；视觉和声音不额外暴露具体能力标识。

05 / 霓虹地下牌局的视听体验

以深蓝黑空间、深色绒面牌桌、青紫灯光和精致卡牌形成统一气质。高对比牌面与金额承担信息，灯带与短促反馈承担气氛。

场景画面反馈声音反馈
大厅与选能力轻微环境光变化，能力卡片聚焦与选择确认。舒缓电子爵士；选择时短促确认声。
发牌与下注卡牌滑入、翻面，筹码汇入底池，行动座位灯带亮起。纸牌声与筹码碰撞，操作确认声简洁。
转牌与河牌公共牌清晰揭示，不用长动画拖延后续决策。平滑增加节奏或氛围层，只由公开阶段驱动。
能力发动本人显示完整效果，对手只显示对应公开动作的通用效果。公开音效同样通用；私密音效仅本机播放。
全押与结算短促强化光效、筹码归属动画、阶段积分变化与冠军庆祝。全押提示、获胜短句与结算声，关键提示时压低 BGM。

音乐至少覆盖准备、对局和结算情境，使用可循环且衔接自然的素材或分层编曲。音效至少覆盖发牌、翻牌、筹码、过牌／弃牌、能力公开动作、轮到自己、计时提醒和结算。具体曲目尚未选定，本文不表示已经制作或取得素材授权。

采用授权明确、允许随游戏分发的素材并保留来源及许可证。音频、字体和美术随游戏本地提供，无 CDN 或在线播放依赖；客户端声音由自己的音量设置控制。

动画不延长服务端行动期限。手机降低粒子、模糊和光效，提供减少动态效果选项；页面返回前台后跳过旧动画。目标是正常设备上操作流畅，优先保证触控响应、卡牌与金额可读。

06 / 房主权威架构与数据边界

房主电脑运行一个本地服务，同时提供网页、静态素材和实时房间连接。朋友在相同局域网打开房主地址；房主界面展示可复制地址和入局二维码。电脑需保持运行，网络需允许设备互通；来宾 Wi-Fi 的设备隔离或本机防火墙可能阻止连接，启动说明需覆盖这两项排查。

电脑浏览器 ─┐
手机浏览器 ─┼─ 操作请求 / 实时状态 ─→ 房主电脑的本地服务
房主浏览器 ─┘                            │
                                        ├─ 房间与座位 / 重连 / 权威计时
                                        ├─ 比赛状态机 / 德州规则 / 能力规则
                                        ├─ Bot：只接收自己的可见信息
                                        └─ 按座位过滤状态
                                               ↓
                           公共状态 + 该座位私密状态 → 对应浏览器

本地静态素材 ─→ 各浏览器的界面、动画与声音
模块职责与接口依赖
德州规则核心输入牌局状态和动作，输出新状态与事件；负责合法下注、发牌、摊牌及边池。可替换的随机源、牌型计算；不依赖浏览器或网络。
能力规则声明触发窗口、消耗、目标、效果和公开范围，通过规则核心执行换牌等受控操作。受限牌局接口与能力定义；不直接发送网络消息。
比赛流程推进 5 × 5 流程、三选一、补发、重置及积分结算，生成阶段事件。德州核心与能力规则。
房间与连接管理座位凭据、动作去重、版本、计时、重连和 Bot 接管，向流程提交合法来源请求。比赛流程、服务端时钟、状态过滤器。
状态过滤从完整状态生成公共视图及指定座位私密视图；公开事件剔除隐藏字段。状态模型与能力公开范围。
陪玩 Bot根据本人视图、合法动作和保守／激进／跟注风格作出选择，使用同一操作入口。过滤后的信息；不能读取完整牌堆或对手秘密。
浏览器呈现渲染响应式牌桌，发送用户意图，将可见事件转为动画和声音。本人状态与可见事件；不裁定胜负或随机结果。
供后续实现参考的消息形状（逻辑接口，不限定技术栈）
ActionRequest { actionId, expectedVersion, actionType, payload }
  座位身份由连接凭据确定，不能信任客户端声称的 seatId。

SeatSnapshot { version, phase, deadline, publicState, selfState }
  publicState: 座位、筹码、下注、公共牌、底池、公开动作、积分。
  selfState: 本人底牌、能力、次数、资源、私密查看结果、候选能力。

  重复 actionId 返回既有结果；过期或非法请求不产生副作用。

技术栈及打包方式留到实施方案选择；本设计确定本地房主服务、浏览器客户端和实时双向连接的边界，不要求云服务。首版以朋友信任为前提，房主进程持有全局信息，无法对抗刻意修改程序的房主。

07 / 断线、后台与异常处理

  • 断线：座位、筹码、能力保留。当前手继续按正常时限自动过牌或弃牌，下一手起由 Bot 接管。构筑阶段断线使用正常超时随机选择规则。
  • 重连：同一浏览器保存座位凭据，连接后获取当前完整本人视图；在下一手开始时交还操作权。等待期间展示接管状态。同一凭据只允许一个有效控制连接。
  • 移动端后台：房主计时不暂停；返回后同步最新状态和必要记录，跳过过期动画，不重复播放积压音效。
  • 房主：关闭房主浏览器不停止独立运行的本地服务。电脑休眠、进程关闭或崩溃会中断比赛；服务终止后无法恢复该局，重新启动需开新局。
  • 输入异常：越权行动、非法金额、无效目标、能力次数不足或版本过期均拒绝，并返回可理解提示及新状态。重复点击不重复扣筹码或消耗能力。
  • 连接失败：显示房主地址、同网检查和重试入口；无法连接时不能假装已经入座或提交操作成功。

08 / 验证标准与后续内容工作

验证维度关键场景与通过标准
德州正确性常规摊牌、公共牌平局、多人不同金额全押、多个边池、短码全押后加注权与余筹分配。每手中筹码守恒，补发只在规定窗口发生。
比赛结算完整推进 25 手；每阶段每个座位当庄一次。重复补发、负排名筹码、二人和多人并列、最终同分均按规则计算；每阶段总发放积分为 11。
能力与秘密换牌无重复、旧牌不回流；非法窗口不能使用能力。侦察信息保持快照。检查实际网络消息及事件，不含其他座位能力、候选或未公开底牌。
Bot1 真人 + 4 Bot 能完成比赛；Bot 能选能力并合法使用。用受限视图驱动决策，风格有差异，不要求达到竞技级水平。
网络与生命周期1–5 真人组合、电脑与手机混合、断线重连、手机后台、重复请求与过期请求。状态一致，控制权只在规定边界交接。
视觉与音频桌面 Chrome／Edge、Android Chrome、iPhone Safari 检查竖屏布局、触控、音频解锁、静音、前后台恢复和减少动态效果。素材能从房主本地加载。
真实体验记录完整局耗时、各环节等待、能力使用率、得分分布与玩家反馈；重点观察弃牌刷资源、侦察与换牌组合、阶段末全押是否成为单一优势打法。

当前验证状态：仅完成设计文档自检；未实现游戏，未运行游戏测试，未验证实际局时或音乐品质。
